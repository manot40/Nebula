# Commands, Plugins & Local Dev Environment

## 1. Implementing Commands (`emu.nebula.command`)

Commands run both from the server stdin console (`Nebula.startConsole()`) and in-game by entering `!<cmd>` or `/<cmd>` in the player profile signature edit dialog (`HandlerPlayerSignatureEdit`) or via `/api/command` (`RemoteHandler`).

`CommandManager` (`src/main/java/emu/nebula/command/CommandManager.java`) auto-discovers all classes in `emu.nebula.command` annotated with `@Command` that implement `CommandHandler`:

```java
@Command(
    label = "give",
    aliases = {"g", "item"},
    permission = "player.give",
    requireTarget = true,
    desc = "!give [item ids...] x(amount) = Sends items through mail."
)
public class GiveCommand implements CommandHandler {
    @Override
    public String execute(CommandArgs args) {
        int amount = Math.max(args.getAmount(), 1);
        // args.getList() holds positional tokens; @uid, xN, lvN, aN, sN, tN, fN are pre-parsed
        return "Give command success, check your mail";
    }
}
```

### `CommandArgs` Built-in Token Parsing
`CommandArgs` (`src/main/java/emu/nebula/command/CommandArgs.java`) automatically strips and parses prefixed tokens from `args.getList()`:
- `@<uid>` -> `args.getTargetUid()` / `args.getTarget()` (console commands require `@<uid>` when `requireTarget = true`)
- `x<amount>` -> `args.getAmount()`
- `lv<n>` / `lvl<n>` -> `args.getLevel()`
- `a<n>`, `s<n>`, `t<n>`, `f<n>` -> ascension, skill, talent, affinity
- `c<n>`, `sc<n>` -> crescendo / sub-note arguments (used by character/disc/build commands)

## 2. Writing Server Plugins (`emu.nebula.plugin`)

`PluginManager` (`src/main/java/emu/nebula/plugin/PluginManager.java`, `API_VERSION = 1`) loads `.jar` files from `./plugins/` at startup:

1. Create a `plugin.json` resource inside the plugin jar matching `Plugin.Config`:
   ```json
   {
     "name": "MyPlugin",
     "description": "Example plugin",
     "version": "1.0.0",
     "mainClass": "com.example.MyPlugin",
     "api": 1,
     "authors": ["author"],
     "loadAfter": []
   }
   ```
2. Extend `emu.nebula.plugin.Plugin` (`src/main/java/emu/nebula/plugin/Plugin.java`) and implement lifecycle hooks:
   - `onLoad()` — called right after plugin JARs are loaded (before `GameContext` / `HttpServer` start).
   - `onEnable()` — called after `HttpServer.start()`.
   - `onDisable()` — plugin teardown hook.
3. Register custom commands via `Nebula.getCommandManager().registerCommand(...)` inside `onEnable()`.

## 3. Building & Verifying Locally

- **JDK**: Java 21 (configured in `build.gradle` toolchain and `.github/workflows/gradle.yml`).
- **Build fat jar** (`gradlew` is not marked executable in git, so invoke with `bash` or run `chmod +x gradlew` first):
  ```bash
  bash ./gradlew jar
  ```
  This runs `injectGitHash` -> writes `src/main/java/emu/nebula/BuildConfig.java` -> outputs `./Nebula.jar`.
- **Compile-only check**:
  ```bash
  bash ./gradlew injectGitHash compileJava
  ```
  Never run `./gradlew compileJava` alone on a fresh checkout because `BuildConfig.java` is gitignored and only generated by `injectGitHash`.
- **Tests**: There is currently no automated test suite (`src/test/` does not exist). Verify edits with `./gradlew jar` and runtime smoke testing.

## 4. Running Nebula & Inspecting Traffic

### Runtime Directory Setup
1. Create `./resources/` containing `bin/` and `language/` folders from datamined game data (see `README.md` or `Dockerfile`).
2. Start the server:
   ```bash
   java -jar Nebula.jar
   ```
   Useful dev flags: `-nohandbook` (faster startup), `-login`, `-game`, `-database`.
3. On first boot, Nebula generates `./data/config.json` (`Config.java`) and `./Nebula Handbook.txt` (IDs for characters, items, potentials).

### Database Options
- **Default (zero setup)**: `internalMongoServer` starts an embedded H2-backed Mongo server (`./data/database.mv` on `localhost:27017`).
- **External / Docker MongoDB**: Set `accountDatabase.useInternal = false` in `./data/config.json`, or run via Docker (`compose.yaml`) which sets `NEBULA_MONGODB_HOST` and `NEBULA_MONGODB_PORT`.

### Useful Dev Flags in `./data/config.json`
- `logOptions.packets = true`: Logs every `RECV` and `SEND` opcode name, numeric ID, and hex payload in `AgentZoneHandler`.
- `logOptions.httpDebug = true`: Enables Javalin/Jetty debug HTTP logging.
- `serverOptions.autoCreateAccount = true`: Automatically creates accounts on login.
- `serverOptions.skipIntro = false`: Set `true` to bypass intro tutorial creation on new players.
- `customDataVersion`: Overrides `versions.json` for testing a newer/older client patch without recompiling.

### Client Redirection (`mitmproxy`)
`mitmproxy/proxy.py` redirects client SDK and game hostnames (`TARGET_HOSTS`) to `http://127.0.0.1:80` (configurable via `SERVER_HOST` / `SERVER_PORT`). Update `TARGET_HOSTS` when testing non-Global regions (`KR`, `JP`, `TW`, `CN`).
